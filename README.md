# Agentic Matrix

A reproducible experiment method and case-study archive for improving an agentic Codex engineering loop without sacrificing correctness, authority, security, or evidence quality.

## Why this repository exists

The first General Codex Engineering Loop experiment on 2026-09-04 tested whether more routing/skill machinery actually improved real engineering work. The result was deliberately conservative: the existing P0 workflow won by non-promotion, while a read-only review-agent showed bounded promise on two defective diffs.

This repository preserves the method so future skills, reviewers, routing policies, memory/context systems, or reasoning configurations can be tested against the then-current real workflow rather than adopted because they sound useful.

## Structure

- `methods/AGENTIC_MATRIX_METHOD_V1_1.md` — reusable current experimental method.
- `methods/AGENTIC_LIVE_TELEMETRY_STANDARD_V1.md` — owner-required native token telemetry, durable usage evidence, and live monitor standard.
- `methods/AGENTIC_TOKEN_ATTRIBUTION_STANDARD_V1.md` — owner-required token-driver attribution, context-component manifests, Pareto/waste diagnosis, and attribution ceilings.
- `methods/AGENTIC_CONTROLLER_EXECUTION_STANDARD_V1.md` — owner-required controller/transport/budget/evidence/review discipline extracted from real LAPIS engineering failures and recoveries.
- `methods/GENERAL_CODEX_ENGINEERING_LOOP_EXPERIMENT_PREREGISTRATION_V1_1.md` — exact frozen 2026-09-04 preregistration.
- `methods/GENERAL_CODEX_ENGINEERING_LOOP_24_RUN_ALLOCATION_V1_1.md` — exact Stage-A allocation.
- `methods/GENERAL_CODEX_PATHWAY_GAP_ANALYZER_V1_1.md` — gap/inefficiency classification and remedy ladder.
- `methods/GENERAL_CODEX_ENGINEERING_LOOP_PEER_REVIEW_DISPOSITION_LEDGER_V1_1.md` — redesign history after adversarial review.
- `methods/GENERAL_CODEX_ENGINEERING_LOOP_OWNER_APPROVAL_PACKAGE_V1_1.md` — original owner-review package.
- `case-studies/` — immutable dated experiment reports.
- `data/` — normalized machine-readable metrics for each run.
- `archive/` — superseded designs retained for provenance.

The operating standards are cross-project method. They do not import LAPIS project authority into another repository and do not create Git, provider, production, acceptance, release, or deployment authority.

The reusable lesson is not "P0 is always best." It is: **new complexity must beat the current real baseline on matched, decision-relevant evidence before it becomes default.**

## Future studies

Create a new dated case-study and metrics file for every experiment. Never rewrite an older study to reflect a newer workflow. Each new study freezes the current P0 baseline, the candidate mechanism, matched task classes, evaluator, authority, MPIDs, holdout, and final artifact identities.

No experiment result creates production, Git, provider, acceptance, or release authority by itself.
